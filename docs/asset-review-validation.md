# 图片复核验证记录（2026-09-30）

## 实现范围

审核页“AI 复核本题图片”使用灰度阈值、连通区域和邻近标注生成候选框，DeepSeek 只选择编号和用途，不能修改坐标。结果先预览、再应用到草稿，保存后写入题库；首次整卷识别尚不自动执行图片复核。

整卷流式识别输出预算显式设为 32768，避免依赖模型较小的默认额度。

## 定位基准

杨浦、松江共 10 道目标题，参考框在调用模型前人工标注。通过条件为四边最大绝对误差不超过 12 像素，且 IoU 不低于 0.85。

| 方法 | 结果 |
| --- | --- |
| 直接输出像素坐标，8 题 | 0/8 |
| 输出归一化坐标，8 题 | 0/8 |
| 旧整卷定位加局部放大复核，8 题 | 2/8 |
| 候选框编号选择，8 题连续三轮整卷调用 | 24/24 |
| 追加两道未参与调参的题 | 2/2 |

这检验的是指定目标图，不代表任意试卷所有图片的召回率。原页、裁剪预览和模型原始响应保留在本地 `tmp/asset-benchmark/`，不上传到仓库。

## 两份新卷全流程

使用生产构建及已配置的 DeepSeek API，在独立数据库和文件副本中重新识别原页，通过实际 HTTP 接口执行入队初始化、整卷识别、逐题图片复核、草稿保存、裁剪文件生成和读取。

| 试卷 | 页数 | 题数 | 保存并读取的图片 |
| --- | --- | --- | --- |
| 崇明区二模答案 | 17 | 21 | 7 |
| 黄浦区二模答案 | 18 | 21 | 11 |

42 道题均通过；同时核对无图题不产生图片，以及有图题的数量和来源页码。保存使用待核查状态，不把接口成功等同于人工审核通过。正式题库未被修改。

首次全卷检查发现了无外框茎叶图漏检，以及紧邻封闭表格的页眉混入。补充细竖线与分散数字的候选检测，封闭表格不吸纳框外文字，并增加回归测试；之后重新完整执行上述两卷验证。此前 10 道定位基准的边界误差仍为 1–5 像素。

最终验证：122 项自动化测试、生产构建及变更文件 ESLint 通过。真实模型结果存在随机性，断线、重叠文字、低质量扫描件仍可能需要手动修正。

## 重现

需要本地保留对应原卷并配置 DeepSeek；以下命令会产生 API 用量：

```sh
node --experimental-strip-types scripts/benchmark-asset-localization.mjs
npm run build
node scripts/verify-asset-review-workflow.mjs
```

全流程测试保留在 `tmp/asset-workflow-<timestamp>/`，包含隔离数据、裁剪图、结果与日志。该目录可能包含本地密钥文件，不应分享或提交。
