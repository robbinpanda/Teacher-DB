# 教学资源管理：当前实现与后续方向

更新：2026-10-12。本文记录本轮实际代码行为；未实现的方向单独列出。

## 产品原则

试卷库统一管理教师的上传原卷和组卷作品。试卷资产应当可再次编辑；导出的 PDF 只是输出格式，不是组卷的持久化模型。

原始试卷、题目、组卷作品是三种对象。文件夹只用于整理，不决定资源来源、共享权限或归档状态。

## 当前存储与关联

默认数据目录为项目下的 `data`，可由 `JIANTI_DATA_DIR` 指定。SQLite 文件为 `teacher-question-bank.sqlite3`，附件位于数据目录的 `files`。

| 对象 | 实体 | 保留内容 |
| --- | --- | --- |
| 上传原卷 | `documents`，`source_kind = uploaded` | 原文件 `original_key`、名称、学科年级、状态、来源元信息、试卷文件夹 `paper_folder_id` |
| 识别结果 | `pages`、`extraction_runs`、`questions`、`question_assets` 等 | 分页图、运行记录、题目、题图、答案和解析、审核状态 |
| 题目 | `questions` | `document_id` 指向来源；`folder_id` 指向个人题目文件夹 |
| 组卷作品 | `papers` | 标题、副标题、`settings_json`、试卷文件夹 `folder_id`、创建和更新时间 |
| 组卷引用 | `paper_items` | `paper_id`、`question_id`、顺序 `position`、分值 `score` |
| 试卷文件夹 | `paper_folders` | 同一教师的原卷和作品共用，可建立子文件夹；与 `question_folders` 独立 |
| 个性化识别方案 | `teaching_skills`、`teaching_skill_trials`、`teaching_skill_usages` | 个人规则、版本、试识别和人工结论、正式识别时的规则快照 |

关联链路：`documents → questions ← paper_items → papers`。

### 明确区分来源

数据库迁移 v4 新增 `documents.source_kind`，取值为 `uploaded / imported / generated`。上传流程默认为 `uploaded`；共享包导入和 AI 变式入库分别显式写入另外两种值。

旧数据只使用项目原有的两个专用来源标记 `application/x-jianti-import` 和 `application/x-jianti-generated` 回填，其他已有文档保留为上传来源。这里沿用已有来源协议，不根据文件名、有无 PDF 或有无解析推测类型。

`getPaperLibrary(ownerId)` 查询当前教师的上传来源及 `papers`，输出显式的 `kind = uploaded / assembled`。共享包来源和 AI 变式的容器文档不会伪装成原卷。即使两个表的 ID 相同，列表键也由类型与 ID 共同组成。

迁移只增加字段和索引，不复制题目或原文件；历史迁移校验不变。更新应用并重启 API 后自动应用 v4。上线前沿用现有备份流程，旧版本程序不能直接读取已经升级到 v4 的数据库。

## 本轮实现

### 试卷库

- 默认“全部试卷”，提供“上传原卷 / 组卷作品”类型切换。
- 默认紧凑表格：名称、类型、学科年级、题量、更新时间、操作；取消顶部统计卡片墙。
- 搜索与排序作用于当前类型、当前文件夹；文件夹管理按需展开，两类试卷均可移动、重命名。
- 上传原卷：有原文件时打开原卷，进入识别/审核，跳转到按该来源筛选的题库；删除原文件时保留题目。
- 组卷作品：继续编辑、独立预览、下载试卷 PDF、下载答案解析、删除作品；学校模式保留布置作业入口。
- 新建组卷进入现有编辑器；上传快捷入口直接打开工作台既有导入抽屉。
- 没有新增“已归档”状态。文件夹整理不冒充归档；原文件已删除的记录显示真实状态并保留来源追溯。
- 未经授权的其他教师不能通过库查询、编辑或预览访问记录。

### 编辑恢复与保存

编辑入口为 `/papers/[paperId]`。读取该作品的 `paper_items` 后，**只用该作品已有题目**恢复 `settings_json` 的 sections。题库仅作为候选题池，不能把整个题库传给恢复函数，否则会自动追加其他题目。

恢复标题、副标题、模板 ID、板块及顺序、分值配置、页边距/字体等样式、答题空间、题图布局、卷首信息、注意事项和解析预览配置。作品中的题目会合并回编辑器候选池，避免被题库默认 2000 条候选上限截断。

`POST /api/papers` 使用固定作品 ID 更新已有记录及引用，不在每次保存时新建作品。空 ID 列表读取返回空列表，不误读取整个题库。已经被引用但重新进入审核的题目仍显示在已有作品中；保存接口会要求审核通过，不默默删掉这些引用。

保存期间又产生新修改时，界面保持“有未保存修改”，禁止把尚未保存的状态当作已保存下载，也不使用服务器返回页面覆盖新的本地输入。浏览器关闭/刷新或点击当前页链接离开时，对未保存内容提示确认。

预览入口 `/papers/[paperId]/preview` 通过当前教师身份查询。专供 PDF 渲染的 `/print` 仍保留原有短期令牌校验。

### 题库

- “我的题库”管理现有真实个人资源；“基础题库”明确显示尚未开放，不把教师上传内容算作平台资源。
- 个人文件夹与年级、题型、知识点、地区、教材、来源试卷分离；筛选可组合。
- 知识点使用收起的选择控件，地区、教材和上传/共享包/变式来源放在更多筛选。
- 来源筛选在后端按 `source_kind` 查询，仍限制当前教师和已审核题目。
- 从原卷跳转时按 `documentId` 查询，避免当前侧栏的学段设置把该原卷题目过滤掉；清除来源后恢复教学范围筛选。
- 区分筛选无结果、文件夹无题、当前教学范围无题、整个个人库无题和请求失败。保留公式/图片、答案解析、选题篮、组卷、共享包和变式能力。

### 教学 Skills

- 首页展示默认方案与可搜索的个人方案，不直接展示长篇 Prompt。
- 创建流程：上传实际支持的 PNG/JPEG/WebP 单张图片（最多 12MB）→ AI 生成已持久化草稿 → 查看概览 → 试识别与人工复核 → 启用复用。
- 详情分“概览 / 测试与效果 / 高级规则”，摘要节选自真实规则文本。名称和规则编辑、默认规则对照、导出、测试历史、基于反馈改进继续保留。
- 沿用“基础规则 + 个人增量规则”、版本校验及每学科年级唯一启用机制。生成不是已验证；修改规则后停用，当前版本重新测试和人工通过后才能启用。
- 导入工作台沿用按学科年级自动选择已启用方案，否则回退默认方案；正式识别保留使用快照。没有额外伪造一个不会生效的方案选择器。

## 沿用的删除与引用语义

1. 同一道题进入多个作品只新增 `paper_items` 引用，不复制 `questions`。
2. 删除组卷作品只删除作品及其关联项，不删除原题。
3. 试卷库提供原卷的 `source_only` 删除：删除原文件、分页与识别运行记录，保留文档来源元信息、题目和裁剪图。记录标为原文件已删除。
4. 工作台原有“连同题目删除”及题库“永久删除题目”能力未改变；它们会影响引用该题的组卷。相关破坏性操作继续保留原有确认提示。
5. 当前组卷使用**实时题目引用**，不是题目内容快照。修改原题会影响引用它的作品；手工永久删除题目会移除作品中的对应引用。此次未擅自改成复制或快照机制。

## 尚需后端支持的方向

### 优先级 1：平台基础题库

当前没有平台资源发布、跨教师只读查询和共享权限模型，所以模卷、名校试卷暂不能浏览。后续最小方案：

- 新增独立平台资源包实体，记录发布状态、类别（模卷/名校试卷）、维护者、学科年级；明确题目与包的成员关系。
- 平台资源使用真实平台归属，不能依赖教师名称、题目标题、考试类型或“未分文件夹”判定。
- 扩展题目搜索、预览、组卷保存与导出权限：教师可读取已发布资源、引用组卷，不能修改或删除平台原题。
- 如果提供“复制到我的题库”，显式记录复制来源并去重；收藏引用与实际复制分别建模。
- 协调资源包下架、原题修订、已有作品可用性和租户隔离后，再开放基础资源浏览入口。

### 优先级 2：作品保存可靠性与版本

- 增加修订号/乐观锁，防止多个浏览器窗口互相覆盖。目前同一作品的并发更新仍以最后成功写入为准。
- 在确认实时引用与快照的产品策略后，设计作品版本、题目快照、模板版本。需兼顾历史输出重现与原题修订。
- 在现有手动保存的基础上做去抖自动保存、离线草稿与冲突恢复；不能静默把不完整状态覆盖已保存作品。
- 题库候选池改为按范围分页查询，当前编辑器最多加载 2000 个候选；已有作品的引用题目不受此候选上限影响。
- 如果要支持真正的归档/回收站，新增相应状态及恢复接口，不复用文件夹或原文件删除字段。

### 优先级 3：Skill 适用性验证

- Skill 创建目前只支持图片，测试使用原样例；PDF 样例、替换测试卷、多样例回归需新增接口及样例实体。
- 若需编辑说明/适用格式、复制和删除方案，增加相应持久化字段及 API；本轮未展示假按钮。
- 当前导入按范围自动选择启用方案。如要按单次上传覆盖方案，需贯通上传、队列、重试和 usage snapshot，不能只加前端下拉框。
- 将审核纠错沉淀为候选改进建议，经过教师确认和测试后更新。不能把一次纠错称为自动学习成功，也不伪造准确率。

## 验证与人工验收

自动化：数据库实测作品更新、引用顺序、来源区分、租户隔离、删除保留题目和非空文件夹保护；浏览器验证类型筛选、来源跳转、恢复编辑、保存期间继续修改、方案编辑持久化、组合筛选与四种桌面宽度。回归覆盖原有工作台与审核流程。

本轮验收：174 项单元测试、27 项浏览器测试全部通过；TypeScript、ESLint、生产构建通过。Windows 沙箱无法执行备份用例的目录链接和重命名，已在正常权限、隔离临时数据目录下重跑通过。新页面在 1366、1440、1680、1920 桌面宽度检查横向溢出，并检查了 1440 宽度实际截图。

随后补充验证试卷和答案解析两个真实 PDF 导出接口（有效 PDF 响应），并再次通过试卷库、Skills 两项浏览器流程。

人工验收重点：使用实际长试卷和题图检查输出分页；使用真实模型服务检查 Skill 生成和跨样例适用性。本轮不会调用付费模型来凭空宣称识别效果提升。

## 2026-10-12 资源页面视觉迭代

- 三页统一管理界面的无衬线字体、标题层级、页边距、按钮和页签；试卷打印字体与数学公式字体继续由原有排版逻辑控制。
- 试卷库合并重复汇总区，使用蓝色原卷、绿色组卷图标与类型标签，标题下保留真实状态。菜单按视口定位，表格不再为菜单预留空白；滚动、缩放窗口、点击外部或 Escape 可关闭菜单。
- 题库默认展示完整宽度列表，文件夹按需展开；仅选题后出现批量操作。搜索和条件集中展示，长题干与操作区分开，来源不再在操作区重复堆叠。
- Skills 默认方案改为紧凑说明条，个人方案以名称、版本、更新时间和启用状态为核心。创建页提供步骤说明、真实图片选择区与模型设置，仍需测试和人工核对才能启用。
- 本轮使用隔离测试数据检查长试卷名、长题干、公式、文件夹和选题操作，检查 1366/1440/1680/1920 桌面宽度及 390 窄屏溢出。截图里的样例仅用于验收，不写入正式题库。

后续 UI 方向：优先在实际大量数据下评估筛选、批量操作与列表密度；逐步统一工作台、模型配置页和组卷编辑器的控件尺寸。若调整组卷编辑器，先整理题目编排与试卷设置的任务入口，再处理预览画布；不以重做视觉为由改变现有保存、引用和删除语义。
